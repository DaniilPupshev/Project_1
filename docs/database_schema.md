# Справочник по структуре базы данных PechVision

Документ описывает таблицы базы данных PechVision: назначение, поля, типы данных,
возможные значения и связи.

База хранит:

- видео с кассовой камеры;
- запуски обработки видео;
- уникальных людей;
- визиты в зону кассы;
- найденные лица;
- сотрудников, которых нужно исключать из потока посетителей;
- чеки;
- связи между визитами и чеками.

## Общие соглашения

### Первичные ключи

Во всех основных таблицах используется поле `id`.

| Поле | Тип | Обязательное | Описание |
|---|---|---:|---|
| `id` | `integer` | Да | Внутренний идентификатор записи в базе данных. |

### Временные поля

Большинство таблиц наследуют поля из `TimestampMixin`.

| Поле | Тип | Обязательное | Описание |
|---|---|---:|---|
| `created_at` | `timestamp with time zone` | Да | Дата и время создания записи. Заполняется PostgreSQL. |
| `updated_at` | `timestamp with time zone` | Да | Дата и время последнего обновления записи. |

### Дополнительные данные

Во многих моделях Python-поле называется `extra_data`, а колонка в БД называется
`metadata`.

| Поле Python | Колонка БД | Тип | Описание |
|---|---|---|---|
| `extra_data` | `metadata` | `jsonb` | Дополнительные технические данные без отдельной колонки. |

Имя `metadata` не используется как Python-атрибут, потому что оно зарезервировано
SQLAlchemy.

### Embeddings

Embeddings хранятся через расширение PostgreSQL `pgvector` в колонках типа
`vector(512)`.

Поля с embeddings:

- `persons.face_embedding`;
- `faces.embedding`;
- `staff_members.face_embedding`.

Для `persons.face_embedding` создан HNSW-индекс с оператором
`vector_cosine_ops`. Он ускоряет поиск ближайшего человека по cosine distance.

## Таблица `videos`

### Назначение

Хранит информацию об исходном видеофайле. Одна запись соответствует одному видео.

### Поля

| Поле | Тип | Обязательное | Описание |
|---|---|---:|---|
| `id` | `integer` | Да | Внутренний ID видео. |
| `source_path` | `varchar(1024)` | Да | Исходный путь к видеофайлу. |
| `stored_path` | `varchar(1024)` | Нет | Путь к видео внутри проекта, если файл был скопирован. |
| `filename` | `varchar(255)` | Да | Имя файла. |
| `camera_name` | `varchar(255)` | Нет | Название камеры, например `Camera 01`. |
| `fps` | `float` | Нет | Частота кадров. |
| `width` | `integer` | Нет | Ширина кадра в пикселях. |
| `height` | `integer` | Нет | Высота кадра в пикселях. |
| `frame_count` | `integer` | Нет | Количество кадров. |
| `duration_seconds` | `float` | Нет | Длительность видео в секундах. |
| `recorded_start_at` | `timestamp with time zone` | Нет | Время начала записи по OCR или ручному вводу. |
| `recorded_end_at` | `timestamp with time zone` | Нет | Время окончания записи по OCR или расчету. |
| `file_sha256` | `varchar(64)` | Нет | SHA-256 содержимого видеофайла. Используется как постоянный идентификатор файла независимо от его имени и пути. |
| `file_size_bytes` | `bigint` | Нет | Размер исходного видеофайла в байтах. |
| `metadata` | `jsonb` | Нет | Дополнительные данные о видео. |
| `created_at` | `timestamp with time zone` | Да | Когда запись создана. |
| `updated_at` | `timestamp with time zone` | Да | Когда запись обновлена. |

### Ограничения

| Имя | Поля | Описание |
|---|---|---|
| `uq_videos_file_sha256` | `file_sha256` | Не позволяет зарегистрировать один и тот же видеофайл повторно, даже если его имя или путь изменились. Для старых записей значение может оставаться `NULL` до повторной регистрации файла. |

### Связи

| Связь | Описание |
|---|---|
| `videos -> processing_runs` | У одного видео может быть несколько запусков обработки. |
| `videos -> visits` | В одном видео может быть несколько визитов. |

## Таблица `processing_runs`

### Назначение

Хранит один запуск обработки видео. Одно и то же видео можно обработать несколько
раз с разными конфигами, моделями или параметрами зон.

### Поля

| Поле | Тип | Обязательное | Описание |
|---|---|---:|---|
| `id` | `integer` | Да | Внутренний ID запуска. |
| `video_id` | `integer` | Да | Ссылка на `videos.id`. |
| `status` | `varchar(50)` | Да | Статус обработки. По умолчанию `pending`. |
| `config_path` | `varchar(1024)` | Нет | Путь к YAML-конфигу запуска. |
| `started_at` | `timestamp with time zone` | Нет | Время начала обработки. |
| `finished_at` | `timestamp with time zone` | Нет | Время завершения обработки. |
| `error_message` | `varchar` | Нет | Сообщение об ошибке, если запуск упал. |
| `config_snapshot` | `jsonb` | Нет | Безопасный снимок конфигурации запуска. Пароль БД сохраняется в скрытом виде. |
| `config_hash` | `varchar(64)` | Нет | SHA-256 параметров, влияющих на обработку видео. |
| `start_frame` | `integer` | Да | Индекс первого кадра диапазона обработки. Для полного видео равен `0`. |
| `frame_limit` | `integer` | Нет | Максимальное количество выбранных кадров для обработки. `NULL` означает обработку до конца видео. |
| `stats` | `jsonb` | Нет | Сводная статистика запуска. |
| `created_at` | `timestamp with time zone` | Да | Когда запись создана. |
| `updated_at` | `timestamp with time zone` | Да | Когда запись обновлена. |

### Возможные значения `status`

| Значение | Описание |
|---|---|
| `pending` | Запуск создан, обработка еще не началась. |
| `running` | Видео обрабатывается. |
| `finished` | Обработка успешно завершена. |
| `failed` | Обработка завершилась ошибкой. |

### Индексы

| Индекс | Поля | Назначение |
|---|---|---|
| `ix_processing_runs_config_hash` | `config_hash` | Ускоряет поиск запусков с одинаковыми параметрами обработки. |

### Связи

| Связь | Описание |
|---|---|
| `processing_runs -> videos` | Запуск относится к одному видео. |
| `processing_runs -> visits` | В рамках запуска создаются визиты. |

## Таблица `persons`

### Назначение

Хранит уникальных людей. Один `Person` может быть связан с несколькими визитами
в одном или разных видео. Объединение выполняется по сходству embeddings лиц.

### Поля

| Поле | Тип | Обязательное | Описание |
|---|---|---:|---|
| `id` | `integer` | Да | Внутренний ID человека. |
| `external_person_key` | `varchar(64)` | Да | Стабильный внешний ключ человека. |
| `first_seen_at` | `timestamp with time zone` | Нет | Когда человек впервые замечен. |
| `last_seen_at` | `timestamp with time zone` | Нет | Когда человек последний раз замечен. |
| `best_face_path` | `varchar(1024)` | Нет | Путь к лучшему изображению лица. |
| `face_embedding` | `vector(512)` | Нет | Нормализованный embedding лучшего лица для идентификации человека. |
| `metadata` | `jsonb` | Нет | Дополнительные данные. |
| `created_at` | `timestamp with time zone` | Да | Когда запись создана. |
| `updated_at` | `timestamp with time zone` | Да | Когда запись обновлена. |

### Формат `external_person_key`

Рекомендуемый формат:

```text
P_<uuid4_hex>
```

Пример:

```text
P_6f2d8e5c0a6b4c8db9a78de35b0c4f91
```

### Индексы и ограничения

| Объект | Поля | Назначение |
|---|---|---|
| Уникальное ограничение | `external_person_key` | Не допускает повторения внешнего ключа человека. |
| `ix_persons_face_embedding_hnsw` | `face_embedding` | Ускоряет поиск ближайшего embedding через cosine distance. |

### Связи

| Связь | Описание |
|---|---|
| `persons -> visits` | У человека может быть несколько визитов. |
| `persons -> faces` | У человека может быть несколько сохраненных лиц. |

## Таблица `visits`

### Назначение

Хранит факт нахождения трека человека в зоне кассы.

`Visit` создается после того, как человек вошел в заданный полигон кассовой зоны и
находился там не меньше `min_visit_seconds`.

### Поля

| Поле | Тип | Обязательное | Описание |
|---|---|---:|---|
| `id` | `integer` | Да | Внутренний ID визита. |
| `event_key` | `varchar(255)` | Да | Стабильный ключ события, используемый для защиты от повторной записи визита. |
| `video_id` | `integer` | Да | Ссылка на `videos.id`. |
| `processing_run_id` | `integer` | Да | Ссылка на `processing_runs.id`. |
| `person_id` | `integer` | Нет | Ссылка на `persons.id`; может быть пустой до идентификации лица. |
| `staff_id` | `integer` | Нет | Ссылка на `staff_members.id`, если визит распознан как сотрудник. |
| `track_id` | `varchar(55)` | Да | ID трека внутри обработки видео. |
| `visit_date` | `date` | Нет | Дата визита. |
| `entered_at` | `timestamp with time zone` | Нет | Время появления в зоне кассы. |
| `left_at` | `timestamp with time zone` | Нет | Время ухода из зоны кассы. |
| `duration_seconds` | `float` | Нет | Длительность нахождения в зоне. |
| `entry_frame_index` | `integer` | Нет | Индекс кадра входа в зону. |
| `exit_frame_index` | `integer` | Нет | Индекс кадра выхода из зоны. |
| `ocr_entered_at` | `timestamp with time zone` | Нет | OCR-время около входа. |
| `ocr_left_at` | `timestamp with time zone` | Нет | OCR-время около выхода. |
| `time_is_estimated` | `boolean` | Да | Признак восстановленного/интерполированного времени. |
| `is_staff` | `boolean` | Да | Признак, что визит относится к сотруднику. |
| `is_group` | `boolean` | Да | Признак группового визита. |
| `metadata` | `jsonb` | Нет | Дополнительные данные визита. |
| `created_at` | `timestamp with time zone` | Да | Когда запись создана. |
| `updated_at` | `timestamp with time zone` | Да | Когда запись обновлена. |

### Возможные значения флагов

| Поле | Значение | Описание |
|---|---:|---|
| `time_is_estimated` | `false` | Время получено напрямую через OCR. |
| `time_is_estimated` | `true` | Время восстановлено по соседним кадрам или интерполяции. |
| `is_staff` | `false` | Визит относится к посетителю. |
| `is_staff` | `true` | Визит относится к сотруднику и исключается из потока посетителей. |
| `is_group` | `false` | Одиночный визит. |
| `is_group` | `true` | Рядом было несколько людей, возможна групповая покупка. |

### Ограничения

| Ограничение | Поля | Назначение |
|---|---|---|
| `uq_visits_event_key` | `event_key` | Не допускает повторной записи одного события визита. |

### Связи

| Связь | Описание |
|---|---|
| `visits -> videos` | Визит относится к одному видео. |
| `visits -> processing_runs` | Визит создан в рамках одного запуска обработки. |
| `visits -> persons` | Визит может быть связан с уникальным человеком. |
| `visits -> staff_members` | Визит может быть связан с сотрудником. |
| `visits -> faces` | У визита может быть несколько найденных лиц. |
| `visits -> receipt_matches` | Визит может быть связан с чеками через matching. |

## Таблица `faces`

### Назначение

Хранит найденные лица, изображения лиц, embeddings, результаты оценки пола и
возраста, а также признаки пригодности изображения для идентификации человека.

Для одного человека может храниться несколько лиц из разных визитов. Часть
качественных изображений помечается как идентификационные эталоны и используется
для последующего распознавания этого человека.

Лицо обязательно относится к визиту, но может не быть связано с `Person`, если
оно не подходит для надежной идентификации.

### Поля

| Поле | Тип | Обязательное | Описание |
|---|---|---:|---|
| `id` | `integer` | Да | Внутренний ID лица. |
| `person_id` | `integer` | Нет | Ссылка на `persons.id`; может быть пустой до идентификации. |
| `visit_id` | `integer` | Да | Ссылка на `visits.id`. |
| `image_path` | `varchar(1024)` | Нет | Путь к сохраненному изображению лица. |
| `frame_index` | `integer` | Нет | Индекс кадра, из которого взято лицо. |
| `quality_score` | `float` | Нет | Оценка качества лица. |
| `identity_quality_score` | `float` | Нет | Итоговая оценка пригодности лица для идентификации. Учитывает уверенность детектора, размер лица, резкость, положение лица и углы поворота головы. |
| `is_identity_eligible` | `boolean` | Да | Показывает, разрешено ли использовать embedding этого лица для идентификации человека. |
| `is_identity_reference` | `boolean` | Да | Показывает, входит ли лицо в текущую галерею идентификационных эталонов персоны. |
| `pose_category` | `varchar(20)` | Нет | Категория ракурса лица: фронтальный, поворот влево, поворот вправо или неизвестный. |
| `embedding` | `vector(512)` | Нет | Нормализованный embedding конкретного лица. |
| `gender` | `varchar(15)` | Нет | Оцененный пол. |
| `gender_confidence` | `float` | Нет | Уверенность определения пола. |
| `age_estimate` | `float` | Нет | Примерный возраст. |
| `age_bucket` | `varchar(20)` | Нет | Возрастная группа. |
| `is_best` | `boolean` | Да | Является ли лицо лучшим кадром. |
| `metadata` | `jsonb` | Нет | Дополнительные данные лица. |
| `created_at` | `timestamp with time zone` | Да | Когда запись создана. |
| `updated_at` | `timestamp with time zone` | Да | Когда запись обновлена. |

### Возможные значения `gender`

| Значение | Описание |
|---|---|
| `male` | Мужчина. |
| `female` | Женщина. |
| `unknown` | Пол не определен или уверенность слишком низкая. |

### Возможные значения `age_bucket`

Примеры:

```text
0-9
10-19
20-29
30-39
40-49
50-59
60+
unknown
```

### Возможные значения `pose_category`

| Значение | Описание |
|---|---|
| `frontal` | Лицо направлено преимущественно в сторону камеры. |
| `left` | Лицо повернуто влево относительно камеры. |
| `right` | Лицо повернуто вправо относительно камеры. |
| `unknown` | Ракурс невозможно надежно определить. |

### Возможные значения идентификационных признаков

| Поле | Значение | Описание |
|---|---|---|
| `is_identity_eligible` | `false` | Лицо хранится для истории и аналитики, но не участвует в идентификации. |
| `is_identity_eligible` | `true` | Лицо достаточно качественное для идентификации. |
| `is_identity_reference` | `false` | Лицо не входит в текущий набор эталонов персоны. |
| `is_identity_reference` | `true` | Лицо используется как один из эталонов персоны. |

`is_identity_reference = true` допускается только для лица с заполненным
`person_id`, заполненным `embedding` и `is_identity_eligible = true`.

### Индексы

| Индекс | Поля | Назначение |
|---|---|---|
| `ix_faces_person_identity_reference` | `person_id`, `is_identity_reference` | Ускоряет получение галереи эталонных лиц конкретной персоны. |

### Связи

| Связь | Описание |
|---|---|
| `faces -> visits` | Лицо найдено в рамках визита. |
| `faces -> persons` | Лицо может быть связано с уникальным человеком. |

## Таблица `staff_members`

### Назначение

Справочник сотрудников, которых нужно исключать из потока посетителей.

На первом этапе это кассиры, но название таблицы позволяет хранить и другой
персонал.

### Поля

| Поле | Тип | Обязательное | Описание |
|---|---|---:|---|
| `id` | `integer` | Да | Внутренний ID сотрудника. |
| `external_staff_key` | `varchar(128)` | Нет | Внешний ключ сотрудника. |
| `full_name` | `varchar(255)` | Нет | Имя, фамилия или внутренняя метка сотрудника. |
| `photo_path` | `varchar(1024)` | Нет | Путь к эталонному фото. |
| `face_embedding` | `vector(512)` | Нет | Нормализованный эталонный embedding лица сотрудника для поиска по cosine distance. |
| `is_active` | `boolean` | Да | Используется ли сотрудник при исключении из потока. |
| `metadata` | `jsonb` | Нет | Дополнительные данные сотрудника. |
| `created_at` | `timestamp with time zone` | Да | Когда запись создана. |
| `updated_at` | `timestamp with time zone` | Да | Когда запись обновлена. |

### Возможные значения `is_active`

| Значение | Описание |
|---|---|
| `true` | Сотрудник участвует в сравнении лиц. |
| `false` | Сотрудник отключен и не используется при сравнении. |

### Связи

| Связь | Описание |
|---|---|
| `staff_members -> visits` | Один сотрудник может быть связан с несколькими визитами, исключенными как персонал. |

## Таблица `receipts`

### Назначение

Хранит чеки, загруженные из CSV, Excel или полученные через API.

### Поля

| Поле | Тип | Обязательное | Описание |
|---|---|---:|---|
| `id` | `integer` | Да | Внутренний ID чека. |
| `external_receipt_id` | `varchar(128)` | Да | ID чека из внешней системы. |
| `tt` | `varchar(120)` | Нет | Торговая точка или подразделение. |
| `opened_at` | `timestamp with time zone` | Да | Время открытия заказа. |
| `closed_at` | `timestamp with time zone` | Да | Время закрытия или оплаты чека. |
| `amount` | `numeric(12, 2)` | Нет | Сумма чека. |
| `table_number` | `integer` | Нет | Номер кассы, стола или рабочего места. |
| `client_external_id` | `varchar(220)` | Нет | ID клиента из чековой или лояльной системы. |
| `source_file` | `varchar(1024)` | Да | Файл-источник, из которого импортирован чек. |
| `raw_data` | `jsonb` | Нет | Оригинальная строка чека в JSON-совместимом виде. |
| `created_at` | `timestamp with time zone` | Да | Когда запись создана. |
| `updated_at` | `timestamp with time zone` | Да | Когда запись обновлена. |

### Соответствие CSV-полям

| CSV | Поле в БД |
|---|---|
| `OrderId` | `external_receipt_id` |
| `TT` | `tt` |
| `openTime` | `opened_at` |
| `dl_tm` | `closed_at` |
| `OrderSum` | `amount` |
| `stol_num` | `table_number` |
| `Client_TTGID` | `client_external_id` |
| вся строка CSV | `raw_data` |

### Связи

| Связь | Описание |
|---|---|
| `receipts -> receipt_matches` | Один чек может иметь одну или несколько связей с визитами. |

## Таблица `receipt_matches`

### Назначение

Хранит результат сопоставления визитов с чеками.

Таблица отвечает на вопрос: какой визит связан с каким чеком и по какому правилу.

### Поля

| Поле | Тип | Обязательное | Описание |
|---|---|---:|---|
| `id` | `integer` | Да | Внутренний ID связи. |
| `visit_id` | `integer` | Да | Ссылка на `visits.id`. |
| `receipt_id` | `integer` | Да | Ссылка на `receipts.id`. |
| `matched_at` | `timestamp with time zone` | Да | Когда связь была создана. |
| `time_delta_seconds` | `float` | Да | Разница во времени между визитом и чеком. |
| `confidence` | `float` | Нет | Уверенность сопоставления. |
| `is_ambiguous` | `boolean` | Да | Признак неоднозначного сопоставления. |
| `is_group_match` | `boolean` | Да | Признак связи чека с группой людей. |
| `policy` | `varchar(50)` | Да | Правило, по которому создана связь. |
| `metadata` | `jsonb` | Нет | Дополнительные данные сопоставления. |
| `created_at` | `timestamp with time zone` | Да | Когда запись создана. |
| `updated_at` | `timestamp with time zone` | Да | Когда запись обновлена. |

### Возможные значения `policy`

| Значение | Описание |
|---|---|
| `closest_with_flag` | Выбран ближайший чек или визит по времени, неоднозначность отмечается флагом. |

### Связи

| Связь | Описание |
|---|---|
| `receipt_matches -> visits` | Связь относится к конкретному визиту. |
| `receipt_matches -> receipts` | Связь относится к конкретному чеку. |

## Схема связей

```text
videos
  ├── processing_runs
  └── visits
        ├── faces
        ├── receipt_matches ─── receipts
        ├── persons
        └── staff_members

persons
  ├── visits
  └── faces

staff_members
  └── visits
```

## Примечания по персональным данным

Таблицы `persons`, `faces` и `staff_members` содержат чувствительные данные:

- изображения лиц;
- embeddings лиц;
- оценку пола;
- оценку возраста.

Эти данные должны храниться локально, не попадать в публичный репозиторий и использоваться только в рамках проекта.
